## Context

`docs/仕様/要求仕様書.md` §7 は「面接セッション」中心の実装済み質問抽出（相手の発話から質問を抽出する）を想定しており、「面接練習モード」（AI が質問そのものを生成する模擬面接）には触れていない。コードベースも同様で、`src/pages/` には Pluely 由来の `app`（オーバーレイ）、`chats`、`audio`、`screenshot`、`responses`、`shortcuts`、`dev`、`settings`、`system-prompts` はあるが、面接ドメイン専用のページは存在しない。DB マイグレーションも `chat-history.sql` と `system-prompts.sql` のみで、Document/Company/InterviewSession 等の §10 データモデル案は未実装。

AI プロバイダー呼び出しは `src/lib/functions/ai-response.function.ts` の `fetchAIResponse` が担い、Dev Space で選択されたプロバイダー種別（カスタム curl テンプレート or Pluely/ネイティブ経由の Tauri コマンド）に応じてブラウザ `fetch` か Tauri コマンドかに分岐する（[プロバイダーとキャプチャ](../../../openwiki/integrations/providers-and-capture.md)参照）。直近の類似実装として `top-bar-transcript-summary-panel` 変更が、会話履歴を使わない単発の AI 変換（要約生成）を `fetchAIResponse` に `history` なし・専用システムプロンプトで呼び出すパターンを確立している。本変更はこれと同じ呼び出しパターンを踏襲する。

## Goals / Non-Goals

**Goals:**
- ユーザーが練習開始前に難易度（初級/中級/上級）を選択できる。
- 選択した難易度に応じて、AI プロバイダーが生成する模擬面接質問の複雑さ・深掘り度を変える。
- 生成された質問セットを画面に一覧表示し、ローカル SQLite に保存する。
- AI プロバイダー未設定時に、既存 UI パターン（例: STT プロバイダー未設定時のメッセージ）と一貫した案内を表示する。

**Non-Goals（本変更のスコープ外。将来の別 change で扱う）:**
- 生成した練習質問への回答例生成・採点・フィードバック。
- 面接中オーバーレイ（§7.8）や面接後レポート（§7.9）との統合。
- 登録資料（職務経歴書・求人票、§7.1-7.2）を参照した質問のパーソナライズ。未登録でも汎用的な質問を生成できることを前提とする。ドキュメント管理機能が実装された場合の統合は別 change とする。
- 質問件数のユーザー設定（本変更では 1 回の生成につき固定 5 問とする）。
- 質問意図分類（§7.6）カテゴリの厳密な自動タグ付け。保存スキーマにはカテゴリ列を持たせるが、本変更では常に NULL とする。
- `docs/仕様/要求仕様書.md` 本体の更新（この機能を正式スコープとして仕様書に反映するかどうかは人間のレビュー判断に委ねる）。

## Decisions

- **新規ページとして独立実装する**: `src/pages/practice/`（`PracticeSetup` 相当のコンポーネント）を新設し、`DashboardLayout` 配下に `/practice` ルートとして追加する。理由: 面接セッション管理（§7.3）や資料管理（§7.1-7.2）が未実装のため、それらに依存する設計にすると本変更が実装不能になる。既存の `Dashboard`/`Chats` などと同列のトップレベルページとして追加するのが、現状のルーティング構造（`src/routes/index.tsx`）に最も自然に収まる。
- **AI 呼び出しは既存の `fetchAIResponse` を再利用する**: `top-bar-transcript-summary-panel` の要約生成と同じパターンで、`history: []`・練習質問生成専用の固定システムプロンプトを渡して呼び出す。`userMessage` には選択された難易度に応じたプロンプト文（例: 初級「基本的な自己紹介・経歴確認レベルの質問」、中級「技術経験の深掘りを含む質問」、上級「高度な技術的圧迫質問・意思決定の理由を問う質問」）を組み立てて渡す。理由: 新規のプロバイダー呼び出し経路を作らず、プロバイダー種別分岐（カスタム HTTP / Tauri コマンド）を含む既存の抽象化をそのまま流用できる。`fetchAIResponse` は非同期ジェネレータ（`AsyncIterable<string>`）であるため、`useSystemAudio.ts` の `generateSummary` と同様に `for await...of` でチャンクを1つの文字列に連結してから、次段のパース処理（改行分割）に渡す。
- **練習質問生成ではグローバル回答設定によるプロンプト拡張を無効化する**: `fetchAIResponse` に後方互換な opt-out 引数（例: `applyResponseSettings?: boolean`、既定値 `true`）を追加し、練習質問生成からは `false` を渡して専用システムプロンプトをそのまま使用する。専用プロンプト自身が「日本語で5問」を明示する。理由: 現行の `fetchAIResponse` は `buildEnhancedSystemPrompt` でユーザーの回答言語設定（既定値は英語）と回答長設定（「短め」は2〜4文）を必ず追記するため、そのまま再利用すると日本語表示および5問生成の要件と競合する。既存呼び出しは引数省略時の挙動を維持する。
- **出力形式は「1行1問、番号なし」をプロンプトで指定し、改行分割でパースする**: AI へのプロンプトで「質問のみを1行ずつ、箇条書き記号や番号を付けずに出力すること」と明示し、レスポンスを改行で分割、空行と先頭の記号（`-`, `1.` 等）を正規表現で除去して質問配列を得る。パース結果がちょうど5件なら質問セットとして採用し、それ以外（0件、1〜4件、6件以上）は生成結果全体を1件のテキストとして表示・保存するフォールバックとする。通常時は5問を生成する要件だが、フォールバック時だけ表示・保存件数が1件になる。理由: 「期待件数から大きく外れる」という曖昧な閾値を実装者判断に残さず、表示件数・保存件数の要件とフォールバックを整合させるため。
- **AI 呼び出し失敗を質問本文として扱わない**: `fetchAIResponse` は例外を投げる場合に加え、カスタム HTTP 経路のネットワークエラー、非2xx、レスポンス解析失敗、ストリーム失敗を英語のエラーテキストとして `yield` する実装である。生成ヘルパーはこれら既存のエラー出力を成功レスポンスから区別し、空レスポンスと併せて失敗として返す。UI は日本語の生成失敗案内と再試行可能な状態を表示し、質問一覧の置換および DB 保存を行わない。理由: プロバイダー障害の文字列が練習質問として表示・永続化されることを防ぐため。
- **保存スキーマは単一テーブル `practice_questions` とし、生成 1 回分を `batch_id` でグルーピングする**: 新規マイグレーション `src-tauri/src/db/migrations/practice-questions.sql` を追加し、`src-tauri/src/db/main.rs::migrations()` に次のバージョン番号で登録する。列: `id`（PK）, `batch_id`（同一生成回の質問をグルーピングする UUID 文字列）, `difficulty`（`beginner`/`intermediate`/`advanced` の文字列 enum 相当）, `question_text`, `category`（nullable, 将来の §7.6 分類との統合用、本変更では常に NULL）, `created_at`。理由: `conversations`/`messages` のような親子2テーブル構成も検討したが、本変更では「生成セット」に質問本文以外のメタデータ（タイトル等）を持たせる要件がなく、`batch_id` 列だけで同一回の質問をグルーピングでき、テーブル数・JOIN を増やさずに済む。将来、生成セット自体にメタデータが必要になった場合は別テーブルへの正規化を別 change で行う。
- **AI プロバイダー未設定時の扱い**: 判定条件は `!selectedAIProvider.provider && !(await shouldUsePluelyAPI())`（`src/hooks/useCompletion.ts` 等と同じ判定）とする。表示位置・トリガーのタイミング（生成前に案内し、開始操作を塞ぐ）は既存の音声パネル（`top-bar-transcription-panel` スペック「STTプロバイダーが選択されていません」、`src/pages/app/components/TranscriptionPanel.tsx`）に倣うが、文言そのものは同一条件で実際に使われている既存メッセージ「設定画面でAIプロバイダーを選択してください」（`src/hooks/useCompletion.ts`, `useChatCompletion.ts` の AI プロバイダー未設定時エラー文言）をそのまま流用する。練習開始ボタンの代わりにこの文言を表示し、生成リクエストは送信しない。理由: 「AIプロバイダーが選択されていません」はコードベース中に実在せず、STT側の文言から類推した新規文言だった。同一条件で既に使われている実在の文言を再利用する方が、真の意味での既存 UI パターンとの一貫性になる。

## Risks / Trade-offs

- [AI の出力が指定フォーマット（1行1問）に厳密に従わない場合、5問に正しく分割されない] → フォールバックとして生レスポンスを1件で表示・保存するため、情報は失われない。パース精度の改善（構造化出力の強制等）は別 change で扱う。
- [`fetchAIResponse` の一部の失敗は例外ではなくテキストとして返る] → 既存のエラー出力を生成ヘルパーで明示的に失敗へ変換し、表示・保存対象から除外する。将来 `fetchAIResponse` のエラー契約を型付きで整理する場合は別 change で扱う。
- [本変更は §7.1-7.3 の未実装機能（資料・応募先・面接セッション）と統合していないため、生成される質問は汎用的なものにとどまり、ユーザー個別の職務経歴・志望動機を反映しない] → Non-Goals として明示。ユーザー承認済みの段階的スコープ縮小であり、将来の統合は別 change とする。
- [新規 AI 呼び出しが追加されるため、設定済みプロバイダーへのリクエスト回数・コストが増加する] → 練習モードはユーザーが明示的に開始するアクションであり、既存のチャット/音声機能同様、ユーザーの意図的な操作に紐づくリクエストである。
- [`fetchAIResponse` のグローバル回答設定が練習質問の言語・件数指示と競合する] → 既定値が従来挙動を保つ opt-out 引数を追加し、練習質問生成だけで無効化する。チャット、音声、要約など既存呼び出しのプロンプト拡張には影響させない。
- [`docs/仕様/要求仕様書.md` に「面接練習モード」の記載がないまま実装が先行する] → 本 design.md と proposal.md で前提・スコープを明示しており、実装前の人間レビューおよび `openspec sync` 時に仕様書側の更新要否を判断できる。

## Migration Plan

- 単一ブランチでの実装・動作確認後、既存のブランチ・リリース戦略に従って main へマージする。
- DB マイグレーションは新規追加のみ（既存マイグレーションの書き換えなし）のため、既存データへの影響はない。
- ロールバック時は、新規ページ・新規関数・新規マイグレーションファイルを取り除くのみで復元可能（既存機能への変更を含まないため）。

## Open Questions

- 「面接練習モード」を `docs/仕様/要求仕様書.md` の正式スコープ（§6, §7, §13）に追加すべきか。追加する場合、どの優先度（§13.1〜13.3）に位置づけるか。
- 難易度による質問生成方針（プロンプト文言）は、実装後にユーザーの手応えを見て調整が必要になる可能性が高い。
