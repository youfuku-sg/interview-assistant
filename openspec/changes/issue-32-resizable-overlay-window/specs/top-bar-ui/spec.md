## MODIFIED Requirements

### Requirement: Top bar layout structure
トップバーは左カラム（アイコン縦並び）と右エリア（文字起こし・要約・AI回答を表示する領域）の2カラム構成でなければならない（SHALL）。左カラムの幅は固定（約40px）、右エリアは残り幅をすべて占める。トップバーの collapsed 時の縦幅は約240pxとし、現状（160px）の1.5倍とする。左カラムの配置順は上から SystemAudioボタン・マイクボタン・設定ボタン・終了ボタン・ドラッグハンドルとする。テキスト入力欄はデフォルトで非表示とする。トップバーのウィンドウはユーザーがOS標準のウィンドウ端ドラッグで自由にリサイズできなければならず（SHALL）、最小幅・最小高さの制約を下回るサイズにはリサイズできない（SHALL NOT）。ポップオーバー開閉に伴う自動高さ調整（collapsed/expanded の切り替え）は、ユーザーが手動で変更した幅を維持したまま高さのみを変更しなければならない（SHALL）。

#### Scenario: 通常時（未キャプチャ）のレイアウトが2カラムである
- **WHEN** アプリが起動し、音声キャプチャが停止中の状態でトップバーが表示される
- **THEN** 左カラムにアイコンボタン群（SystemAudioボタン・マイクボタン・設定ボタン・終了ボタン・ドラッグハンドル）が縦に並んで表示される
- **AND** 右エリアに文字起こしパネル・要約パネル・AI回答パネルが表示される

#### Scenario: 左カラムのアイコンが正しい順序で縦に並ぶ
- **WHEN** トップバーが表示される
- **THEN** 上から順に SystemAudioボタン、マイクボタン、設定ボタン、終了ボタン、ドラッグハンドルが縦方向に配置される

#### Scenario: トップバーの collapsed 縦幅が約240pxである
- **WHEN** ポップオーバーが閉じている状態（collapsed）でトップバーが表示される
- **THEN** ウィンドウの高さが約240pxである

#### Scenario: 音声キャプチャ中も2カラム構成を維持する
- **WHEN** システム音声のキャプチャが開始される
- **THEN** 左カラムにステータス表示、右エリアにオーディオビジュアライザーが表示される
- **AND** 2カラムのレイアウト構造が維持される

#### Scenario: テキスト入力欄はデフォルトで非表示である
- **WHEN** トップバーが表示される
- **THEN** 右エリアにテキスト入力欄は表示されない

#### Scenario: 終了ボタンを押すとアプリが終了する
- **WHEN** ユーザーが左カラムの終了ボタンを押す
- **THEN** アプリケーションプロセスが終了する

#### Scenario: ユーザーがウィンドウ端をドラッグして自由にリサイズできる
- **WHEN** ユーザーがトップバーウィンドウの端（縁）をドラッグする
- **THEN** ウィンドウの幅・高さがドラッグに応じて連続的に変化する

#### Scenario: 最小サイズを下回るリサイズはできない
- **WHEN** ユーザーがウィンドウを最小幅・最小高さの制約より小さくしようとドラッグする
- **THEN** ウィンドウのサイズは設定された最小幅・最小高さより小さくならない

#### Scenario: 手動リサイズ後もポップオーバー開閉時の自動高さ調整で幅が巻き戻らない
- **WHEN** ユーザーがウィンドウ幅を手動でリサイズした後、ポップオーバーを開閉する
- **THEN** 自動高さ調整(collapsed/expanded の切り替え)により高さは変化する
- **AND** ユーザーが手動で設定した幅は変化しない

#### Scenario: 手動でリサイズした高さがポップオーバーを開閉していないのに巻き戻らない
- **WHEN** ユーザーがウィンドウ高さを手動でドラッグリサイズし、その後ポップオーバーを開閉するなどの操作をしていない状態で、画面内の他の要素（文字起こしテキストの更新等）が変化する
- **THEN** ユーザーが手動で設定した高さは、collapsed/expanded の自動高さ調整によって `240px`/`600px` に巻き戻らない
