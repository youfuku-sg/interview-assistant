## Context

`src/pages/audio/components/AudioSelection.tsx` は、`Select`（`@/components`、shadcn/radix ベース）を用いてマイク（`selectedAudioDevices.input`）とシステム音声（`selectedAudioDevices.output`）をそれぞれ独立した `Select` として表示している。現状すでにトリガーおよび各 `SelectItem` に `MicIcon` / `HeadphonesIcon`（lucide-react）を表示しているが、両セクションの `SelectTrigger` は同じクラス（`border-1 border-input/50 focus:border-primary/50`）を共有しており、アイコン以外の視覚差分がない。デバイス一覧は `get_input_devices` / `get_output_devices`（Tauri コマンド）から取得し、`{ id, name, is_default }` の配列として保持する。バックエンドのデバイス列挙ロジックは種別（マイク/システム音声）を返さないため、UI側は呼び出し元のセクション（`input`/`output`）で種別を判断している。

## Goals / Non-Goals

**Goals:**
- マイクとシステム音声のトリガー・ドロップダウン項目を、アイコンに加えて配色で見分けられるようにする。
- 折りたたまれたトリガーだけを見ても種別が分かるようにする（開かないと分からない状態を解消する）。
- アイコンに意味的なラベル（`aria-label` または視覚的に隠したテキスト）を付与し、スクリーンリーダー利用時にも種別が伝わるようにする。

**Non-Goals:**
- デバイス列挙ロジック（Rust側の `get_input_devices` / `get_output_devices`、`src-tauri/src/speaker/`）の変更は行わない。返却データに種別フラグを追加する等のバックエンド変更はスコープ外。
- Bluetooth／USB／仮想デバイスなど、マイク・システム音声以外のサブタイプの識別は今回のスコープ外。
- 設定画面以外（オーバーレイのマイクボタン等、`Audio.tsx`）でのデバイス表示改善は対象外。

## Decisions

- **配色の実装方法**: Tailwind のユーティリティクラスで、マイクセクションには既存の `primary` 系統、システム音声セクションには `secondary`（または既存デザイントークンの中から視覚的に区別できる色）を `SelectTrigger` の枠線・アイコン色に適用する。新規デザイントークンは追加せず、既存の `@/components` のカラー変数を再利用する。理由: 新しい配色ルールを追加すると他画面との一貫性が崩れるため、既存トークンの使い分けに留める。
- **アイコン強調**: 現状の `SelectItem` 内アイコン表示はそのまま維持し、選択中の項目にはトリガーと同じ色のアイコンを表示することで「今のセクションが何であるか」を視覚的に一致させる。新しいアイコン種別（Bluetooth等）の追加は行わない。
- **アクセシビリティラベル**: 各 `SelectTrigger` のアイコンに `aria-hidden="true"` を設定し、`Header`（`title="マイク"` / `title="システム音声"`）が既にテキストラベルとして機能しているため、追加の `aria-label` は `SelectTrigger` 自体（`aria-label="マイクデバイスを選択"` 等）に付与する。理由: アイコン単体に意味を持たせるのではなく、既存のテキスト構造を補強する形にする。

## Risks / Trade-offs

- [配色をセクションごとに固定すると、ダークモード／ライトモードでコントラスト比が不十分になる可能性がある] → 実装時に両テーマで目視確認し、必要に応じて既存のテーマ変数（`text-primary` 等、明暗自動調整されるトークン）を使う。
- [デバイス種別の判別性向上が主観的な改善であり、定量的な受け入れ基準を設定しにくい] → Issue本文の「マイクとシステム音声の区別がつきにくい」という主訴に対し、色分け＋アイコンの組み合わせで解消したとみなし、動作確認（`docs/仕様/要求仕様書.md` の対象範囲外の主観評価）はスクリーンショットベースで行う。

## Migration Plan

- 単一ブランチでの実装・動作確認後、既存のブランチ・リリース戦略に従ってmainへリリースする。データ・DBスキーマの変更は伴わない。
- ロールバック時は `AudioSelection.tsx` の見た目に関する変更を直前コミットに戻すのみで復元可能。
