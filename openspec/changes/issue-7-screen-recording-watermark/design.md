## Context

メインオーバーレイウィンドウ（`src-tauri/tauri.conf.json` の `windows[0]`）は `"contentProtected": true` を持ち、`create_dashboard_window`（`src-tauri/src/window.rs`）で作成されるダッシュボードウィンドウも同様に `content_protected(true)` を設定している。Tauri/OS レベルのこの設定は、Windows では `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 相当の効果を持ち、対象ウィンドウをスクリーンショット・画面共有・録画から完全に除外する。

Issue #7 は、画面共有・録画中に本アプリが動作中であることを示す小さなウォーターマークを出したいという要望である。これは要求仕様書 §8.6（倫理と利用方針）が「検知されない」「隠れて使える」ことの訴求を明確に避けている点と整合する — 現状の完全非表示設計を、ユーザー自身が透明性のために緩和できる選択肢を提供するものである。

一方で、`contentProtected` は Tauri のウィンドウ単位の設定であり、1 つのウィンドウの一部だけをキャプチャに写す／写さないという制御はできない。したがって、ウォーターマークを既存のオーバーレイ（質問・回答支援など機密情報を含む）と同じウィンドウに描画すると、ウォーターマークもろとも録画から除外され、Issue の意図を達成できない。

技術的な制約として、任意の外部アプリ（Zoom、Teams、OBS 等）が「いまこの瞬間に画面を録画・共有しているかどうか」をクロスプラットフォームかつ信頼性高く検知する一般的な API は存在しない。Windows・macOS ごとに非公式・不安定な手法（DXGI Desktop Duplication の利用検知など）はあるが、個人利用アプリの範囲でメンテナンスするには複雑すぎる。

## Goals / Non-Goals

**Goals:**
- 画面共有・録画に確実に写り込む、本アプリ稼働を示す小さなウォーターマークを提供する。
- 既存オーバーレイ（質問・回答・回答方針などの機密情報）の `contentProtected` による秘匿は維持する。
- ユーザーが設定でウォーターマークの表示有無を切り替えられるようにする（任意）。

**Non-Goals:**
- 他アプリによる実際の画面キャプチャ／録画セッションをリアルタイムに検知すること（OS 依存かつ非公式 API に頼るため対象外とする）。
- ウォーターマークに動的なセッション情報（面接社名、時刻など)を埋め込むこと。単純な固定表示に留める。
- macOS 固有の高度な検証（本プロジェクトは Windows ビルド・配布が主対象。`docs/仕様/CI.md` 参照）。

## Decisions

### 1. 「録画検知」ではなく「常時表示」を採用する
録画・画面共有の開始/終了を検知するロジックは実装せず、オーバーレイが表示されている間はウォーターマードも常時表示する。ウォーターマーク自体を `contentProtected: false`（キャプチャ除外なし）にしておけば、ユーザーが実際に画面を共有・録画した瞬間、自動的にその中に写り込む。これにより「録画中だけ表示する」という複雑で信頼性の低い検知ロジックを避けつつ、Issue の要件（録画・共有中に写ること）を満たす。

*代替案として検討した「録画検知 API を実装し、検知時のみ表示する」は、Windows/macOS で信頼できる汎用 API が存在せず、個人利用アプリの保守コストに見合わないため却下した。*

### 2. 専用の新規ウィンドウとして実装する（既存オーバーレイとは分離）
ウォーターマークは、メインオーバーレイ（`contentProtected: true` のまま）とは別の、小さく透過・クリックスルー・`contentProtected: false` の新規ウィンドウとして実装する。`create_dashboard_window`（`src-tauri/src/window.rs`）と同様に `WebviewWindowBuilder` を用いて `src-tauri/src/window.rs` に `create_watermark_window` 相当の関数を追加し、`src-tauri/src/lib.rs` でセットアップ時に生成する。

*代替案「メインオーバーレイの `contentProtected` を全体で false にする」は、質問・回答支援など秘匿すべき情報まで画面共有に写り込んでしまうため却下した。*

### 3. クリックスルー・最小限の表示内容
ウォーターマークウィンドウは `alwaysOnTop`、`skipTaskbar`、マウスイベント透過（可能な場合）を設定し、面接中の操作を妨げないようにする。表示内容はアプリ名または小さなロゴ＋簡潔な文言（例:「Interview-Pilot 使用中」）のみとし、半透明・小サイズで画面の隅（例: 右下）に配置する。

### 4. 設定でオン/オフを切り替え可能にする
ウォーターマークの表示要否は、他の面接支援関連設定と同様にローカル設定（`src-tauri/src/db/` 経由、または既存の secure/local 設定ストレージ）に保存し、設定画面からトグルできるようにする。デフォルト値（オン/オフどちらを既定にするか）は実装時に要決定（Open Questions 参照）。

## Risks / Trade-offs

- [新規ウィンドウを追加すると、既存のウィンドウ位置調整（`position_window_top_center` 等）やマルチウィンドウのライフサイクル管理と干渉する可能性がある] → ウォーターマークウィンドウはメインオーバーレイの表示/非表示・移動にシンプルに追従させず、独立した固定位置（画面隅）に配置することで結合を減らす。
- [ユーザーが「隠れて使いたい」目的でこの機能をオフにできてしまう場合、§8.6 の倫理方針が意図する透明性が骨抜きになる] → デフォルトのオン/オフ方針、およびオフを許可するかどうかは Open Questions として明示し、実装前に人間のレビューで確定する。
- [クリックスルー設定は OS ごとに実装が異なり、Windows/macOS で挙動差が出ることがある] → CI・配布は現状 Windows が主対象（`docs/仕様/CI.md`）のため、Windows での動作確認を優先し、macOS 固有の挙動差は既知の制約として記録する。
- [常時表示のウォーターマークが、録画していない通常利用時にも常に画面に表示され続け、ユーザー体験上のノイズになる] → 小型・半透明・隅配置とし、設定でオフにできるようにすることで影響を最小化する。

## Migration Plan

1. `src-tauri/src/window.rs` にウォーターマークウィンドウ生成関数を追加し、`src-tauri/src/lib.rs` のセットアップ処理から呼び出す。
2. ウォーターマークウィンドウ用のフロントエンドルート／コンポーネントを `src/routes/` 配下に追加する。
3. 設定の永続化（オン/オフ）を既存の設定ストレージ機構に追加し、設定画面 UI（`src/pages/dev/` または `src/pages/settings` 相当）にトグルを追加する。
4. Windows 上で実際に画面共有（Zoom/Teams 等）や画面録画ソフトを使い、ウォーターマークが録画・共有先に写ることを手動検証する（[テストガイダンス](../../../openwiki/testing/testing-guidance.md) 参照）。
5. ロールバックは、新規ウィンドウ生成呼び出しと設定トグルを無効化するだけで既存オーバーレイの挙動には影響しない。

## Open Questions

- ウォーターマークの表示テキスト／ロゴの具体的なデザイン（文言、サイズ、位置、不透明度）は未決定。
- 設定でのオン/オフのデフォルト値、および「常にオンで変更不可」とするか「ユーザーが自由にオフにできる」とするかは、§8.6 の倫理方針との整合性を踏まえて人間による決定が必要。
- macOS でのクリックスルー・`contentProtected: false` 挙動の検証は本 MVP の範囲に含めるか、Windows 優先で先送りするかは未決定。
