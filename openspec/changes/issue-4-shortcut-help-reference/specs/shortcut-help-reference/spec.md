## Purpose

キーボードショートカットの一覧を、編集操作なしにいつでも確認できるようにする。設定画面（`/shortcuts`）と新設のヘルプ画面（`/help`）の両方から、現在有効な全ショートカットとそのキー割り当てを読み取り専用で一覧できるようにする。

## ADDED Requirements

### Requirement: 設定画面での読み取り専用ショートカット一覧
`/shortcuts` 画面は、既存のショートカット編集UI（`ShortcutManager`）とは別に、全ショートカットアクションとその現在のキー割り当てを編集操作なしで確認できる一覧セクションを表示しなければならない（SHALL）。この一覧は `getAllShortcutActions` が返す全アクションと `getShortcutsConfig` が返す現在のバインディングを表示対象とする。

#### Scenario: 設定画面を開くと一覧がすぐに見える
- **WHEN** ユーザーが `/shortcuts` 画面を開く
- **THEN** どの行も編集モードに入っていない状態で、全ショートカットの名前・説明・現在のキー割り当てが一覧表示される

#### Scenario: 一覧の表示は編集状態に影響しない
- **WHEN** ユーザーが `ShortcutManager` 内のいずれかのショートカットを編集モードにする、または無効化する
- **THEN** 読み取り専用の一覧セクションは操作対象外であり、`update_shortcuts` を呼び出さない

### Requirement: ヘルプ画面からのショートカット一覧アクセス
アプリケーションは新しい `/help` 画面を提供し、サイドバーのメイン `menu` 項目として「ヘルプ」を表示しなければならない（SHALL）。`/help` 画面には、`/shortcuts` 画面の読み取り専用一覧と同じデータソース（`getAllShortcutActions` / `getShortcutsConfig`）に基づくショートカット一覧が表示される。

#### Scenario: サイドバーからヘルプ画面に遷移できる
- **WHEN** ユーザーがサイドバーの「ヘルプ」項目をクリックする
- **THEN** `/help` 画面に遷移し、現在有効な全ショートカットの名前・説明・キー割り当てが表示される

#### Scenario: ヘルプ画面の一覧は編集不可である
- **WHEN** ユーザーが `/help` 画面のショートカット一覧を見る
- **THEN** トグルスイッチや「変更」ボタンなどショートカットを変更する操作は表示されない

### Requirement: 一覧表示の内容の一貫性
設定画面とヘルプ画面に表示されるショートカット一覧は、同じ現在のキー割り当てを表示しなければならない（SHALL）。一方の画面でショートカットのキーが変更された場合、次にもう一方の画面を開いたときに更新後のキーが反映される。

#### Scenario: 設定画面での変更がヘルプ画面の表示に反映される
- **WHEN** ユーザーが `/shortcuts` 画面でショートカットのキーを変更し、その後 `/help` 画面を開く
- **THEN** `/help` 画面の一覧には変更後のキーが表示される
